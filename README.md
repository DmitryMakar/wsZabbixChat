# wsZabbixChat Platform (v1.0)

**wsZabbixChat** — это специализированная коммуникационная платформа для системных администраторов и инженеров эксплуатации Zabbix. Проект решает классическую проблему оперативного оповещения: трансляция критических триггеров и алертов из Zabbix напрямую в интерактивный WebSocket-чат реального времени с поддержкой приватных диалогов между дежурными администраторами.

---

## 📺 Особенности реализации:
1. Клиент-серверная архитектура на базе протокола **WebSockets**.
2. Легковесный производительный бэкенд на **Node.js** взамен громоздких компилируемых решений.
3. Интеграция Zabbix через вебхуки и специализированный мост (`wsBridge`).
4. Автоматизированное управление жизненным циклом платформы с помощью bash-скриптов.

---

## 📂 Структура проекта (Architecture Overview)

Архитектура платформы разделена на три логических компонента: центральный сервер (`wsServer`), интеграционный шлюз (`wsBridge`) и веб-интерфейс (`wsClient`).

```text
.
├── install.sh             # Скрипт автоматической установки зависимостей платформы
├── deinstall.sh           # Скрипт корректного удаления платформы
├── startChat.sh           # Глобальный запуск всей платформы (Server + Bridge)
├── stopChat.sh            # Глобальный останов всей платформы
├── statusChat.sh          # Глобальная проверка статуса процессов
├── displayLogs.sh         # Интерактивный просмотр логов чата в реальном времени
├── purgeLogs.sh           # Очистка лог-файлов сервера
├── testChat.sh            # Комплексный тест проверки доступности портов
│
├── wsServer/              # Центральный WebSocket-сервер чата
│   ├── wsServer.js        # Логика сервера: авторизация, роутинг PUBLIC/PRIVATE сообщений, история
│   ├── config.json        # Конфигурация локального порта сервера
│   ├── package.json       # Зависимости Node.js (пакет 'ws')
│   ├── startServer.sh     # Изолированный запуск сервера в фоне через PM2
│   ├── stopServer.sh      # Изолированный останов сервера
│   └── statusServer.sh    # Статус процесса сервера
│
├── wsBridge/              # Шлюз-транслятор для алертов Zabbix
│   ├── wsBridge.js        # Скрипт приема HTTP Webhook от Zabbix и форвардинга в сокет чата
│   ├── config.json        # Адрес подключения к сокет-серверу
│   ├── curl.sh            # Нативный инструмент генерации HTTP-запроса
│   ├── sendTest.sh        # Скрипт симуляции отправки алерта Zabbix
│   ├── startBridge.sh     # Изолированный запуск шлюза через PM2
│   ├── stopBridge.sh      # Изолированный останов шлюза
│   └── statusBridge.sh    # Статус процесса шлюза
│
└── wsClient/zabbixchat/   # Фронтенд (Браузерное приложение администратора)
    ├── index.html         # HTML5 разметка интерфейса мессенджера
    ├── style.css          # Современные стили (Bubbles сообщений, алерты Zabbix, приватный режим)
    ├── chat.js            # Асинхронная логика работы с WebSocket (UI и события)
    ├── config.json        # Адрес подключения фронтенда к WSS/WS серверу
    └── icq.mp3            # Звуковое уведомление о новых алертах / сообщениях
```

## 🛠️ Автоматизация управления процессами (Управление в один клик)

Для удобства развертывания в корневой директории проекта подготовлены bash-скрипты автоматизации. Перед запуском убедитесь, что скрипты имеют права на исполнение (`chmod +x *.sh`).

### 1. Первичная настройка
*   `./install.sh` — Разворачивает локальные зависимости (`npm install`) в папках `wsServer` и `wsBridge`.

### 2. Запуск и Останов
*   `./startChat.sh` — Запускает `wsServer` и шлюз `wsBridge` в фоновом режиме под управлением демона `pm2`. Чат становится доступен для пользователей и Zabbix.
*   `./stopChat.sh` — Корректно завершает работу всех фоновых процессов платформы, предотвращая утечки памяти и занятые порты.

### 3. Diagnostics и Мониторинг
*   `./statusChat.sh` — Выводит таблицу со статусом процессов (CPU, RAM, Uptime, Restart Count) из менеджера `pm2`, а также актуальный журнал сервера.
*   `./testChat.sh` — Отправляет тестовое сообщение на платформу Zabbix, вызывающее срабатывание триггера, генерацию и отправку двух алертов с платформы Zabbix через wsBridge на wsServer и конечным пользователям (wsClient), отображающихся в чате в виде сообщений от бота Zabbix Server.
*   `./displayLogs.sh` — Выводит на экран текущий журнал работы сервера.
*   `./purgeLogs.sh` — Скрипт очистки файла `chat.log` на сервере для предотвращения переполнения дискового пространства.

### 4. Полное удаление
*   `./deinstall.sh` — Останавливает и удаляет процессы из pm2, очищает кэш и удаляет папки `node_modules`, после чего папка платформы wsZabbixChat может быть окончательно удалена, либо решение вновь инсталлировано скриптом install.sh.

## 🚀 Пошаговое развертывание платформы

### Предварительные требования (Pre-requisites)
Перед началом развертывания платформы убедитесь, что на вашем сервере выполнены следующие условия:
*   **Операционная система:** Linux (Ubuntu/Debian/RHEL/CentOS) с доступом к терминалу.
*   **Среда выполнения:** Установлен **Node.js** (рекомендуемая версия v16+ или v18+ LTS).
*   **Менеджер пакетов:** Установлен **npm** или **pnpm** для подгрузки зависимостей.
*   **Сетевые утилиты:** Наличие установленного пакета **curl** (необходим для работы диагностических скриптов).
*   **Платформа мониторинга:** Развернутый и функционирующий сервер **Zabbix** (с возможностью настройки исходящих вебхуков).
*   **Веб-сервер:** Установленный **Nginx** или **Apache** для хостинга клиентской веб-части и проксирования защищенных WebSocket-соединений (`wss://`).

### Шаг 1: Размещение проекта на Linux-сервере
Склонируйте либо раскройте архив проекта в удобную вам директорию (например, домашнюю) на своем Linux-сервере с запущенной на нем платформой Zabbix.

```bash
cd
git clone https://github.com/DmitryMakar/wsZabbixChat.git
```

В результате у вас должна появиться папка проекта `wsZabbixChat`.

Из вложенной папки `wsZabbixChat/wsClient/` скопируйте папку `zabbixchat` в любую доступную директорию вашего веб-сервера Nginx или Apache. Проверьте ее доступность извне, например, на тестовом стенде аналогичный адрес: 
`https://www.dmpsy.ru/training/zabbixchat/` 

### Шаг 2: Установка
Перейдите в директорию проекта на вашем Linux-сервере и выполните установку зависимостей:
```bash
cd ~/wsZabbixChat
chmod +x *.sh wsServer/*.sh wsBridge/*.sh
./install.sh
```

### Шаг 3: Конфигурация портов и адресов
1. Откройте `wsServer/config.json` и задайте внутренний порт (по умолчанию `3777`).
2. Откройте `wsClient/zabbixchat/config.json` и укажите внешний адрес вашего WebSocket-сервера (например, `wss://yourdomain.ru/ws`, если используется Nginx Reverse Proxy, или `ws://IP_СЕРВЕРА:3777` для локальных тестов).

### Шаг 4: Интеграция с Zabbix (Настройка Webhook)
Для отсылки уведомлений с платформы Zabbix на `wsBridge` настройте Webhook так, как это описано в Лекции 6:
[Инструкция по настройке оповещений (PDF)](https://www.dmpsy.ru/training/lectures/lecture_06_zabbix_72_configuring_alerts.pdf)
либо (более подробно) в материалах Лекции 12 курса Zabbix.

*NB. Для проверки работы шлюза без Zabbix вы можете запустить тестовый скрипт симуляции из папки моста:*
```bash
cd wsBridge
./curl.sh
```

### Шаг 5: Запуск платформы
Запустите систему в фоновом режиме под управлением PM2 и проверьте статус её компонентов:
```bash
./startChat.sh
./statusChat.sh
```

### Шаг 6: Останов платформы
При необходимости проведения технических работ или изменения конфигурации остановите все фоновые процессы платформы командой:
```bash
./stopChat.sh
```

## 🔒 Безопасность и правила чата
*   **Изоляция приватных сообщений:** Сообщения типа `PRIVATE_MSG` логируются на сервере исключительно для целей технического аудита, но алгоритм подгрузки истории (`HISTORY_REPLY`) **гарантированно отсекает** их. При перезагрузке страницы ни один сторонний пользователь не сможет получить доступ к вашей приватной переписке с коллегами.
*   **Reverse Proxy:** В продуктивной среде настоятельно рекомендуется разворачивать платформу за веб-сервером **Nginx** с настроенным SSL-сертификатом (Let's Encrypt) для обеспечения шифрования трафика (`wss://`).
